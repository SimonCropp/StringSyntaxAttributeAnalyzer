# SSA002 — Source has no StringSyntax

| Severity | Code fix | Applies with `dotnet format` |
|----------|----------|------------------------------|
| Warning  | Yes      | Yes |

Fires when the source of a flow (argument, right-hand side of an assignment, property/field initializer, or one operand of an equality check) carries no annotation but the target does. The analyzer can't tell whether the value really holds the target's syntax or whether this is a mix-up, so it asks for the source to be annotated.


## Example

```cs
public class Target
{
    public void Consume([StringSyntax(StringSyntaxAttribute.Regex)] string value) { }
}

public class Holder
{
    public string Value { get; set; }

    public void Use(Target target) => target.Consume(Value);
}
```

Build output:

```
SSA002: property 'Holder.Value' has no StringSyntax attribute but flows to parameter 'value' of method 'Target.Consume', which is [StringSyntax("Regex")]. Fix: add [StringSyntax("Regex")] to property 'Holder.Value' (line 8).
```

The `Fix:` clause names the exact attribute to write and the line of the declaration to put it on. When the declaration is in another file the path is included: `(D:\src\Holder.cs:8)`.

The attribute named is the one that fits the *source's* declaration kind, which is not always the one the target carries:

 * A property, field, or parameter source gets `[StringSyntax("...")]`.
 * A **method** source gets `[ReturnSyntax("...")]` — `StringSyntaxAttribute` has `AttributeUsage(Field | Parameter | Property)`, so it cannot describe a return value. See "`[ReturnSyntax(...)]` on methods" in the readme.
 * A **local** source gets a `// language=<token>` comment, since C# permits no attributes on locals.
 * A union target suggests the matching `[UnionSyntax(...)]`.


## How to fix

Pick one:

1. **Annotate the source.** Add the attribute from the message to the source declaration. This is what the code fix does.
2. **Rename the source** so a name convention infers the syntax: `Value` → `PageHtml`, a parameter `text` → `bodyHtml`. Same effect, no attribute — but only when `stringsyntax.name_conventions` is enabled. See "Name conventions" in the readme.
3. **The value is not of that syntax at all.** Then the call site is wrong and SSA002 has found a bug. Pass the right value.

Apply option 1 across a whole project in one go:

```
dotnet format analyzers --diagnostics SSA002
```

For a target annotated `[UnionSyntax("Json", "Xml")]` the IDE offers one fix per option plus the combined `[UnionSyntax("Json", "Xml")]`; the batch command applies the combined form. For a local, the union produces `// language=json`, `// language=csv`, and the pipe-delimited `// language=json|csv`.


## When it does not fire

 * The untagged source is a string literal, an interpolated string, a concatenation, an `await`, or any other expression the analyzer can't trace to a declaration. These are **Unknown**, not "missing", and are deliberately ignored — otherwise every `"foo"` passed to a `[StringSyntax]` parameter would warn.
 * The source is declared in a namespace matched by `stringsyntax.suppressed_target_namespaces` (default `System*,Microsoft*`). Library authors can't retroactively annotate their APIs, so the warning would offer nothing actionable — `string.Format` and `sb.ToString()` stay quiet.
 * The source is in an assembly the generator confirmed carries no `[StringSyntax]` anywhere (`KnownUnannotatedAssemblies`) — a third-party library that hasn't adopted the attribute.
 * The source's **name** already implies the target's syntax (parameter `html` flowing into `[StringSyntax("Html")]`). Adding the attribute would produce something SSA008 would then flag as redundant. This suppression applies whether or not name conventions are enabled.
 * The target is a union that includes `"Text"`. An unannotated string *is* plain text, so the union already accepts it. Scoped to unions — a strict `[StringSyntax("Text")]` still fires.


## Suppressing

```cs
#pragma warning disable SSA002 // <reason this source can't or shouldn't be annotated>
```

To silence a whole third-party namespace instead, add it to `.editorconfig`:

```ini
stringsyntax.suppressed_target_namespaces = System*,Microsoft*,MyCompany.Legacy*
```
