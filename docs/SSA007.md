# SSA007 — Annotation can be written as a shortcut attribute

| Severity | Code fix | Applies with `dotnet format` |
|----------|----------|------------------------------|
| Warning  | Yes      | Yes |

**Opt-in.** Fires only when shortcut attributes are enabled. See "Shortcut attributes" in the readme.

When enabled, the source generator emits one `internal sealed class <Name>Attribute` per known syntax constant, so `[StringSyntax("Html")]` can be written `[Html]`. SSA007 flags the long forms so a codebase can be migrated in a single apply-all.

Cosmetic — the analyzer reads both forms identically.


## Example

```xml
<PropertyGroup>
  <StringSyntaxAnalyzer_EmitShortcutAttributes>true</StringSyntaxAnalyzer_EmitShortcutAttributes>
</PropertyGroup>
```

```cs
public class Holder
{
    [StringSyntax("Html")]
    public string Value { get; set; }
}
```

Build output:

```
SSA007: The "Html" annotation on property 'Holder.Value' can be written as the shortcut attribute. Fix: replace it with [Html].
```


## How to fix

Replace the attribute with the shortcut. The code fix offers "Replace with `[Html]`" — or "Replace with `[return: Json]`" when the annotation is a `[ReturnSyntax(...)]` on a method.

```
dotnet format analyzers --diagnostics SSA007
```

The reported name is the shortcut's canonical casing: `[StringSyntax("html")]` and `[StringSyntax("Html")]` both resolve to `[Html]`.


## When it does not fire

 * Shortcut attributes are not enabled. This is the default — the rule is silent in a project that hasn't opted in.
 * The value has no matching shortcut. Only known syntax constants get a generated attribute.
 * The annotation is a multi-option `[UnionSyntax(...)]`. There is no single shortcut for a set of syntaxes.


## Suppressing

Turn the whole rule off by not opting in to shortcut attributes, or locally:

```cs
#pragma warning disable SSA007 // long form kept for consistency with generated code
```
