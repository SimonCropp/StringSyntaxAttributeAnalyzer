# SSA008 — Annotation is redundant under a name convention

| Severity | Code fix | Applies with `dotnet format` |
|----------|----------|------------------------------|
| Warning  | Yes      | Yes |

**Opt-in.** Fires only when name conventions are enabled:

```ini
stringsyntax.name_conventions = enabled
```

With conventions on, a declaration whose *name* matches a known convention is already treated as annotated. SSA008 flags an explicit annotation that says exactly what the name already says.


## Example

```cs
public class Holder
{
    [StringSyntax("Html")]
    public string PageHtml { get; set; }
}
```

Build output:

```
SSA008: The "Html" annotation on property 'Holder.PageHtml' is redundant: the name already matches the Html convention. Fix: remove the annotation.
```

The same applies to a local whose `// language=` comment restates its name:

```cs
// language=html
var pageHtml = Load();
```


## How to fix

Pick one:

1. **Remove the annotation.** This is what the code fix does — it deletes the attribute, or strips the `// language=` trivia for a local.
2. **Rename the declaration**, if the *name* is the part that is wrong. `pageHtml` holding JSON is a naming bug the convention has surfaced.

```
dotnet format analyzers --diagnostics SSA008
```


## The convention list

| Value      | Matches        | Example suffixes               |
|------------|----------------|--------------------------------|
| `Uri`      | `uri`, `url`   | `pageUrl`, `apiUri`, `baseUrl` |
| `Html`     | `html`         | `pageHtml`, `bodyHtml`         |
| `Json`     | `json`         | `payloadJson`, `requestJson`   |
| `Xml`      | `xml`          | `configXml`, `responseXml`     |
| `Regex`    | `regex`        | `pathRegex`, `nameRegex`       |
| `Sql`      | `sql`          | `selectSql`, `querySql`        |
| `Csv`      | `csv`          | `rowCsv`, `exportCsv`          |
| `Yaml`     | `yaml`         | `manifestYaml`, `configYaml`   |
| `Markdown` | `markdown`     | `bodyMarkdown`, `notesMarkdown`|
| `Email`    | `email`        | `userEmail`, `contactEmail`    |

Matching is case-insensitive on the whole name, or on a PascalCase suffix — so `pageHtml` matches but `myhtml` does not, because a word boundary is required. A field's leading underscores are punctuation and are stripped first, so `_pageHtml` matches as `pageHtml` and `_html` as `html`.

Format-style constants (`DateTimeFormat`, `NumericFormat`) and the generic `Text` are deliberately absent — their natural variable names (`format`, `text`) are too broad to promote safely.


## When it does not fire

 * Name conventions are not enabled. This is the default.
 * The annotation is a multi-option `[UnionSyntax(...)]`. A single-name convention can't replace a set of syntaxes without dropping the others.
 * The annotation's value differs from what the name implies — that is not redundancy, and no diagnostic is raised for it here.
 * The declaration is a method or a `[ReturnSyntax]` annotation. The convention applies to member and local *names*; a method named `GetUrl` does not carry the syntax through its return value.


## Suppressing

```cs
#pragma warning disable SSA008 // explicit annotation kept for readers who don't know the convention
```
