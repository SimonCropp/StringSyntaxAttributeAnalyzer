# SSA006 — Single-option `[UnionSyntax]` should be `[StringSyntax]`

| Severity | Code fix | Applies with `dotnet format` |
|----------|----------|------------------------------|
| Warning  | Yes      | Yes |

Fires on a `[UnionSyntax(...)]` written with exactly one option. `[UnionSyntax]` exists to express a choice between several syntaxes; with one option it is a longer spelling of `[StringSyntax]`.

Cosmetic — the analyzer reads both forms identically, so this changes nothing about which other diagnostics fire.


## Example

```cs
public class Holder
{
    [UnionSyntax("Json")]
    public string Value { get; set; }
}
```

Build output:

```
SSA006: [UnionSyntax("Json")] on property 'Holder.Value' has only one option. Fix: replace it with [StringSyntax("Json")].
```


## How to fix

Replace the attribute. The code fix does it in place, preserving the value:

```
dotnet format analyzers --diagnostics SSA006
```

Or add the second option, if the single-option union was a half-finished edit and the member really does accept more than one syntax.


## When it does not fire

 * `[UnionSyntax()]` with **no** options. That is a different shape of mistake: "has only one option" would be a lie, and the fix would emit `[StringSyntax("")]`, which is worse than staying silent.
 * `[UnionSyntax("A", "B")]` — two or more options is the attribute doing its job.


## Suppressing

```cs
#pragma warning disable SSA006 // second option lands in the next commit
```
