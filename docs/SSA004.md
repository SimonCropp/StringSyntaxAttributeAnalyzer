# SSA004 — Equality between mismatched StringSyntax values

| Severity | Code fix | Applies with `dotnet format` |
|----------|----------|------------------------------|
| Warning  | No       | No |

The equality counterpart of [SSA001](SSA001.md). Fires on `==` / `!=` when both operands carry an annotation and their value sets do not overlap.

Two strings of different syntaxes are rarely meaningfully equal. A regex is not a date format; an HTML fragment is not a JSON document. A comparison between them is almost always two similarly-shaped values that got crossed.


## Example

```cs
public class Holder
{
    [StringSyntax(StringSyntaxAttribute.Regex)]
    public string Pattern { get; set; }

    [StringSyntax(StringSyntaxAttribute.DateTimeFormat)]
    public string Format { get; set; }

    public bool Same() => Pattern == Format;
}
```

Build output:

```
SSA004: property 'Holder.Pattern' is [StringSyntax("Regex")] but is compared with property 'Holder.Format', which is [StringSyntax("DateTimeFormat")]. Fix: annotate property 'Holder.Format' (line 6) as [StringSyntax("Regex")], or compare a value that is [StringSyntax("DateTimeFormat")].
```

The line in the `Fix:` clause is the declaration to edit. A declaration's span starts at its attribute list, so for an already-annotated member the line points at the attribute — which is the thing to change.


## How to fix

There is **no code fix**, for the same reason as [SSA001](SSA001.md): both sides already carry an annotation, so an automatic fix would have to guess which one is wrong. Pick one:

1. **One of the annotations is wrong.** Correct it.
2. **The comparison is wrong.** Then SSA004 has found a real bug — the two values were never the same thing.
3. **The comparison is deliberately syntax-agnostic** — an emptiness check, a cache-key equality, a test assertion on raw text. Suppress it locally with a reason.


## When it does not fire

 * Either operand is **Unknown** — a literal, a local without a `// language=` comment, a concatenation, an `await`. Comparing against a literal is routine and fine.
 * Either operand is `[StringSyntax("*")]`.
 * The value sets overlap on at least one value.


## Suppressing

```cs
#pragma warning disable SSA004 // comparing raw text, syntax is irrelevant here
```
