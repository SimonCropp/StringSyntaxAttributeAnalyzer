# SSA003 — Target has no StringSyntax

| Severity | Code fix | Applies with `dotnet format` |
|----------|----------|------------------------------|
| Warning  | Yes      | Yes |

The mirror of [SSA002](SSA002.md). Fires when the source of a flow carries an annotation but the target does not, so the syntax is lost from that point on — anything reading the target sees a bare `string` and no tooling downstream knows what it holds.


## Example

```cs
public class Target
{
    public void Consume(string value) { }
}

public class Holder
{
    [StringSyntax(StringSyntaxAttribute.Regex)]
    public string Value { get; set; }

    public void Use(Target target) => target.Consume(Value);
}
```

Build output:

```
SSA003: property 'Holder.Value' is [StringSyntax("Regex")] but flows to parameter 'value' of method 'Target.Consume', which has no StringSyntax attribute. Fix: add [StringSyntax("Regex")] to parameter 'value' of method 'Target.Consume' (line 3).
```

The `Fix:` clause names the attribute to write and the line of the declaration to put it on; a declaration in another file is given as `(D:\src\Target.cs:3)`. A union source suggests the matching `[UnionSyntax(...)]`, and a method target would be told to add `[ReturnSyntax(...)]`.


## How to fix

Pick one:

1. **Annotate the target.** Add the attribute from the message to the target declaration. This is what the code fix does.
2. **Rename the target** so a name convention infers the syntax, when `stringsyntax.name_conventions` is enabled.
3. **The target genuinely accepts anything.** Annotate it `[StringSyntax("*")]` — the explicit "any syntax" wildcard, meant for passthrough APIs like loggers and snapshot testers. This is a real answer, not a silencing trick, but only when it is true of every caller.

Apply option 1 across a whole project in one go:

```
dotnet format analyzers --diagnostics SSA003
```

Do **not** fix SSA003 by deleting the source's annotation. That removes the information the rule exists to propagate and will usually trade one warning for none while making the codebase worse.


## When it does not fire

 * The source is **Unknown** — a literal, a concatenation, an `await`, or any expression the analyzer can't trace to a declaration.
 * The source is `[StringSyntax("*")]`.
 * The target is declared in a namespace matched by `stringsyntax.suppressed_target_namespaces` (default `System*,Microsoft*`), or in an assembly known to carry no `[StringSyntax]` anywhere. A consumer can't annotate `Console.WriteLine`.
 * The target is `object`, `params object?[]`, or an unannotated generic `T`. These are generic value slots — `logger.Info("processing {P}", pattern)` was never going to honour a syntax contract on `pattern`, so the syntax isn't meaningfully being "dropped".
 * The target's **name** already matches the source's syntax convention (source `[Html]` flowing into a parameter named `html`). Treated as self-annotating, whether or not name conventions are enabled.


## Suppressing

```cs
#pragma warning disable SSA003 // <reason the target should stay unannotated>
```

To silence a whole namespace, use the `.editorconfig` knob shown in [SSA002](SSA002.md).
